<Chapter id="intuition" title="The model does not receive words" objective="See the cut before the algorithm.">

You read “unbelievable” as one word. A model receives a list of integers. Something in front of the model decided where the string breaks, and which integer each piece gets. That decision is the tokenizer. Change it, and the model is looking at a different sequence, even though the letters on the page did not change.

This figure makes the cut visible. It does not contain a model. The vocabulary is written by hand for the demonstration. A production tokenizer is learned from a corpus. The lesson below says what was learned, and what this figure refuses to pretend.

</Chapter>

<Chapter id="mechanism" title="Two cuts of the same string" objective="Predict the pieces before you press the button.">

Words mode matches a run of letters, a run of digits, a run of whitespace, or a single other mark. A word stays together. A space is its own piece, including a trailing space. The id for any whitespace run is the id of a single space.

Pieces mode walks the string from the left and takes the longest vocabulary entry that matches the lowercase text at the current position. The vocabulary is a short list of fragments — the, ing, able, tion, cat, sat, un, on, mat, pre — plus the letters, the digits, and a few marks, tried longest first. If nothing matches, it takes one character.

So “unbelievable” in Pieces becomes “un”, then the letters of “believ” one at a time, then “able”. “the cat sat” is made of fragments that are in the list, plus spaces, so those words stay whole. The same letters take a different path depending on whether a longer entry exists.

</Chapter>

<Chapter id="mathematics" title="Longest match, and the algorithm this is not" objective="State the rule the Pieces button actually runs.">

At position i, with the remainder r, Pieces chooses

<Equation tex="p = \arg\max_{v \in V,\; r \text{ starts with } v} |v|" />

and then advances by <Equation tex="|p|" display={false} />. <Equation tex="V" display={false} /> is the designed vocabulary. The id is the index of p in that vocabulary, starting at 1. A character that is not in it gets a fallback id. Those fallback ids are not a learned unknown token. They are a hash into a side range so the figure can still show a chip.

A real byte-pair encoding does not start from a list someone typed. It starts from characters, counts adjacent pairs in a corpus, merges the most frequent pair, and repeats. The vocabulary is the set of merges. Longest match at run time is then a reasonable way to apply a vocabulary that was built that way. This figure skips the counting. The fragments were chosen so that a rare word falls apart and a few common words do not.

That is why a trailing space matters. The space is in the vocabulary as its own entry. The model, if there were one, would see an extra position. Prompts that differ by a space are different sequences.

</Chapter>

<Chapter id="experiment" title="Break a word, then spare one" objective="Use both modes on one string.">

Type unbelievable. Words should show one letter-run. Pieces should show un, then single letters, then able.

Type “the cat sat on the mat”. Pieces should keep those words, because each of them is an entry, and should still show the spaces as pieces. Add a space at the end and count one more chip.

Nothing here is the vocabulary of a named model. If a chip boundary surprises you, the vocabulary above is the complete explanation.

</Chapter>

<Chapter id="apply" title="What the cut changes downstream" objective="Connect the pieces to attention and to the next-token distribution.">

Attention mixes positions. If “unbelievable” is eight positions, there are eight places to look, and none of them is the word. The next-token distribution is a distribution over ids, not over dictionary words. Temperature, sampling, and greedy choice all happen after this cut.

A practitioner’s failure mode is to debug a generation in words when the model mis-cut the word. Another is to compare two tokenizers by how “natural” the pieces look. The pieces are a compression of the training text. They are not a theory of morphology, even when they sometimes coincide with one.

The [embedding space](/studio/embedding-space) places eight of these kinds of pieces in two planes. The planes are drawn by hand, so a neighbour there is a fact about the drawing.

</Chapter>
