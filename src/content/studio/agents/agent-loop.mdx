<Chapter id="stages" title="Four lines of state" objective="Name the object each stop is holding.">

Observe holds the question and an empty tool result. Decide holds a proposal: get_balance, account 14. Act holds the schema’s verdict. The account is required and it is a number, so the call is accepted. Result holds what the tool returned.

The buttons move you along that list. They do not call a model. The proposal was written with the page.

</Chapter>

<Chapter id="fail" title="The failure is a value, not a tone" objective="Separate the record from the sentence about it.">

Fail the tool. The result state becomes “error: unknown account”, and the loop stops because the account was not read. The sentence underneath can still say that the model mentioned 40. That sentence is what a transcript grader sees. The error is what the account balance actually is: unknown.

A check that reads the sentence passes. A check that reads the state fails. They are grading different objects.

</Chapter>

<Chapter id="schema" title="Acceptance is not success" objective="See that the schema and the tool answer different questions.">

Go back to Act after the failure. The schema line is unchanged. It asked whether the call was shaped correctly. It did not ask whether account 14 exists. A schema can refuse a string in a numeric field. It cannot, by itself, know that the account is missing. That fact arrives only as the tool’s result.

</Chapter>
